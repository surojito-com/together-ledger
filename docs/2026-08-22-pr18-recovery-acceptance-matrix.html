TOGETHER LEDGER / PR18

Production recovery acceptance matrix

A release is recoverable only when protected configuration, a fresh encrypted backup, and evidence of its offsite copy agree. These checks are deliberately operational; they do not inspect personal journey content.

Test caseWhat to proveExpected resultDefect / boundary
TC-00310Run the recovery preflight with the protected production environment file absent, non-root-owned, or not mode 0600.The preflight stops before any deployment action.Prevents configuration disappearing at reboot or being made broadly readable.
TC-00320Run the backup with the persistent recipient file missing, malformed, or unreadable.No encrypted output is treated as successful; the error names the missing safeguard.Closes the run-time-recipient gap left after PR13.
TC-00330Run one production backup with valid protected configuration.A new encrypted dump and matching SHA-256 sidecar exist; checksum verification passes.Never use a partial encrypted file as a recovery point.
TC-00340Run the offsite backup service using the restricted backup uploader identity.The uploader creates the encrypted pair and a root-only local receipt that records the exact archive name and checksum.The service identity is not an application credential and cannot read, alter, or delete old backups.
TC-00350Open the private owner view of the configured Google Cloud backup bucket.The current dump and its SHA-256 sidecar are visible; neither object is public.Manual owner confirmation remains a useful independent check because the uploader is intentionally write-only. The private bucket URL belongs in the owner runbook, not this public repository.
TC-00360Run the recovery preflight once the newest local encrypted pair and offsite receipt agree and are younger than the allowed age.The preflight passes. If either becomes stale or mismatched, it fails closed.This is the deployment gate, not a claim that a restore has already been performed.
TC-00370Enable the daily timer only after TC-00340 and TC-00360 pass; review the next scheduled run.The timer is enabled, persistent across reboot, and its journal records a successful backup and copy.A scheduled backup is not a substitute for a periodic isolated restore drill.

Release boundary: PR18 does not move together-ledger.com, expose private ports, add a mobile app, or place any recovery secret in Git or the application container.
